# AWS Certified SysOps Administrator Associate Training — Hands-On Labs

Course code: TGS-2024051413
Version: v5.0

Twelve connected AWS operations labs are scheduled at four labs per day. Detailed procedures are contained here and in the Learner Guide; the slide deck remains concept-led.

## Day 1 · [Lab 01 — Build an Observability and Incident Detection Baseline](Lab-01-observability-incident-baseline/README.md)

Apply K1, K3, K4, A1 and A4 by creating a dashboard, alarm, CloudTrail evidence query and EventBridge detection rule for one tagged workload.

## Day 1 · [Lab 02 — Automate Event-Driven Incident Triage](Lab-02-event-driven-incident-response/README.md)

Apply K3, K4, A1 and A4 by routing a controlled AWS event through EventBridge, invoking a least-privilege remediation function and preserving an auditable triage record.

## Day 1 · [Lab 03 — Operate an EC2 Fleet with Systems Manager](Lab-03-ec2-ssm-patching-automation/README.md)

Apply K3, K5, A3 and A5 by onboarding a managed node, using Session Manager and Run Command, assessing patch compliance and executing a controlled Automation runbook.

## Day 1 · [Lab 04 — Deploy and Test a Multi-AZ Highly Available Service](Lab-04-ha-autoscaling-failover/README.md)

Apply K4, K5, A3 and A5 by deploying an ALB and Auto Scaling service across two Availability Zones, testing health-based recovery and recording a controlled change.

## Day 2 · [Lab 05 — Control Infrastructure Change and Configuration Drift](Lab-05-cloudformation-automation-drift/README.md)

Apply K3, K4, A4 and A5 by validating a CloudFormation template, reviewing a change set, detecting drift and using a Systems Manager Automation runbook with verification.

## Day 2 · [Lab 06 — Prove Backup and Restore Readiness](Lab-06-backup-restore-assurance/README.md)

Apply K4, A1, A4 and A6 by protecting an S3/EBS-style workload, restoring into isolation and measuring actual recovery evidence.

## Day 2 · [Lab 07 — Build a Multi-Account Compliance Evidence Flow](Lab-07-config-security-compliance/README.md)

Apply K1, K3, A1 and A7 by evaluating required tags and encryption, aggregating findings and documenting a controlled remediation exception.

## Day 2 · [Lab 08 — Diagnose IAM Access and Protect Data with KMS](Lab-08-iam-kms-data-protection/README.md)

Apply K1, K3, A1 and A7 by explaining an access decision, narrowing permissions and verifying encryption and key-policy behaviour.

## Day 3 · [Lab 09 — Troubleshoot a VPC Connectivity Path](Lab-09-vpc-path-diagnostics/README.md)

Apply K2 and A2 by isolating a failed request through DNS, routes, security groups, network ACLs, target health and VPC Flow Logs.

## Day 3 · [Lab 10 — Operate DNS and Content-Delivery Failover](Lab-10-route53-cloudfront-failover/README.md)

Apply K2 and A2 by configuring health-aware DNS and CloudFront behaviour, then proving client-visible routing and cache outcomes.

## Day 3 · [Lab 11 — Diagnose Storage and Database Performance, Then Recover](Lab-11-storage-database-recovery/README.md)

Apply K1, K4, A1, A4 and A6 by correlating EBS/RDS signals, selecting a safe change and validating data recovery.

## Day 3 · [Lab 12 — Capstone — Resolve a Multi-Service CloudOps Incident](Lab-12-integrated-incident-capstone/README.md)

Apply A1–A7 in one connected incident by detecting impact, isolating the failed boundary, restoring service, validating data and documenting service-quality improvements.
